# ComfyUI 双语提示词检查器 v1.1.0

这是一个用于整理、检查和翻译 Anima / Danbooru 风格提示词的 ComfyUI 自定义节点。它既可以作为普通英文提示词输入框使用，也可以把提示词拆成可选择的英文标签、中文解释和详细词库记录。

节点本身不会加载生图模型，也不会改变采样器、LoRA 或模型权重。工作流实际接收到的内容始终来自节点的“英文提示词（实际输出）”。

## 一、适合谁使用

- 希望用中文理解英文 Danbooru 标签的新手。
- 经常整理 Anima 提示词、角色标签、动作、服装和镜头词汇的用户。
- 需要个人中英词库、收藏、搜索和社区词库包的用户。
- 希望通过 Ollama、LM Studio 或 OpenAI 兼容 API 翻译、优化提示词的用户。

核心检查、内置词库和纯词库翻译不需要额外模型。只有主动使用模型翻译或优化功能时，才需要配置 Ollama 或外部 API。

## 二、安装方法

1. 关闭 ComfyUI。
2. 解压发布包中的 `ComfyUI-Bilingual-Prompt-Inspector` 文件夹。
3. 将整个文件夹复制到：

   `ComfyUI/custom_nodes/ComfyUI-Bilingual-Prompt-Inspector`

4. 启动 ComfyUI。
5. 浏览器按一次 `Ctrl+F5` 强制刷新。
6. 在节点菜单中选择：

   `文本 → 提示词工具 → 双语提示词检查器（英文输出）`

本扩展只使用 Python 标准库、ComfyUI 已包含的 `aiohttp` 和浏览器原生功能，不需要单独执行 `pip install`。

### 从旧版覆盖升级

1. 关闭 ComfyUI；建议先在词库管理器导出一次个人词库作为额外备份。
2. 不要删除旧的 `ComfyUI-Bilingual-Prompt-Inspector` 文件夹。
3. 把新版同名文件夹复制到 `custom_nodes`，选择合并目录并替换同名程序文件。不要使用会先清空目标目录的镜像同步或“删除后解压”。
4. 启动 ComfyUI，浏览器按 `Ctrl+F5` 强制刷新。

v1.1.0 发布包不携带 `data/user_tags.json`、`data/pack_settings.json`、`data/large_dictionary.json`、社区词库、大型数据库、助手配置或运行身份文件，因此正常覆盖升级不会改写这些本机数据。收藏和最近使用保存在浏览器本地存储中，存储键与 v1.0.0 保持一致；但更换浏览器配置、ComfyUI 域名或端口时，浏览器会视为另一份本地存储。

### 从 GitHub 安装

普通用户优先下载 GitHub Releases 中的公开 ZIP，不要下载或提交大型数据库。开发者也可以在 `ComfyUI/custom_nodes` 目录执行：

```powershell
git clone https://github.com/Qiongyi44/ComfyUI-Bilingual-Prompt-Inspector.git
```

克隆完成后重启 ComfyUI，并按 `Ctrl+F5`。仓库不包含 API 配置、个人词库、运行时身份和可选大型数据库；这些内容只在用户本机使用时创建。

## 三、最基础的连接方法

1. 在节点顶部英文区域输入提示词。
2. 将右侧的“英文提示词”输出连接到支持文本输入的节点，或连接到对应模型的文本编码节点。
3. 点击“完成编辑”，英文内容会切换为可联动的标签视图。
4. 正常运行工作流即可。

中文解释、词库分类、收藏状态和诊断提示不会进入模型。只有顶部英文实际输出会被传递。

## 四、英文区域怎么使用

英文区域有两种模式。

节点顶部的 ComfyUI 原始英文文本框始终保留并可直接编辑；下方检查器英文区域提供更适合标签操作的文本／联动视图，两处使用同一份实际输出。

### 文本编辑模式

- 空节点默认进入文本编辑模式。
- 可以正常粘贴、输入和整体修改提示词。
- 输入过程中不会突然切换视图。
- 点击“完成编辑”、按 `Ctrl+Enter` 或点击节点其他位置后，切换到标签视图。
- 英文编辑框右下角可以拖动调整高度。
- 英文区域的“清空”第一次点击只进入确认状态，第二次点击“确认清空”才会清空实际英文输出；清空后按钮会变成“撤销”，也仍支持 `Ctrl+Z`。这不会触发删除节点。

### 标签联动模式

- 每个标签显示为独立块。
- 自然语言描述保持为一个完整块，不会按句子内部逗号拆开。
- 点击英文标签时，对应中文标签和底部明细行会同步显示蓝色。
- 双击英文或中文标签可打开权重编辑器，设置 `0–3` 的权重、选择常用预设或清除权重。
- 选中标签后，可以按 `Delete`、`Backspace` 或点击 `×` 删除。
- 点击“编辑文本”可重新返回普通文本框。

删除操作支持 `Ctrl+Z` 撤销和 `Ctrl+Y` 重做。节点按标签的具体位置删除，因此相同标签出现多次时只删除当前选中的一项。

## 五、绿色中文区域怎么使用

绿色区域默认显示英文提示词对应的中文解释。

- 点击中文标签，会同步高亮对应英文标签和明细行。
- 未收录标签以橙色警告块显示。
- 选中中文标签后同样可以删除对应英文标签。
- 中文解释仅供阅读，不会自动写入模型输入。

点击“编辑文本”后，绿色区域会变成可输入的草稿框，支持中文、英文和中英混合内容。处理结果先保留在这里，只有用户点击“同步到英文输出”并确认预览后，才会覆盖实际英文提示词。

绿色区域不提供单独的清空按钮；点击“返回联动”即可回到由英文实际输出生成的中文标签视图，避免把临时中文草稿误认为独立输出。

## 六、三个翻译与优化按钮

### 仅翻译

- 中文或中英混合内容：翻译为英文。
- 纯英文内容：翻译为中文。
- 不主动扩写或优化。
- 尽量保留标签顺序、权重、角色名、画师前缀和否定关系。
- 单标签翻译仍会拦截模型擅自返回多个标签；自然语言翻译允许正常增加逗号，并保持为完整句子或段落。

### 翻译并优化

- 先理解和翻译输入，再整理成适合 Anima 的英文提示词。
- 尝试去除重复和明显冲突。
- 标签放在前面，自然语言说明放在末尾。
- 结果不会自动同步，必须先人工检查。

### 优化为 Anima

- 只接受英文输入。
- 不负责中译英。
- 用于整理标签写法、去重、检查冲突和规范顺序。
- 输出会检查 Anima 提示词允许的常用标点。

外部模型可能误解人物、动作或关系。涉及角色数量、左右位置、身体动作和成人内容时，应在同步前逐项检查结果。

## 七、Anima 顺序整理

“按官方顺序整理”是手动按钮，不会在输入时自动运行。按下后会先显示预览，并把每个非空分类单独放在一行：

1. 质量、元数据、年份、安全等级。
2. 人数。
3. 角色。
4. 作品或系列。
5. 画师。
6. 外观与服装。
7. 表情、动作和姿势。
8. 镜头与构图。
9. 画风。
10. 场景、背景和光线。
11. 末尾自然语言描述。
12. 无法可靠判断的待确认分类。

排序只移动已经存在的内容，不主动增加标签，也不会在实际输出中写入分类标题。整理完成后，中文联动区会以“左侧分类名、右侧标签”的表格显示各分类；这只是可视化视图。权重、LoRA、`@` 画师、重复标签、`BREAK` / `AND` 分段及自然语言内部逗号都会保留；同一分类内保持原顺序。

## 八、自动识别模式

检查器可以识别：

- 纯标签列表。
- 纯自然语言。
- 标签加末尾自然语言。
- 自然语言后接标签，以及“标签—自然语言—标签”的夹心结构。
- 带翻译要求和正文的内容。
- 数值权重、括号、`@` 画师前缀、LoRA 尖括号语法和换行分段。

自动识别使用本地规则，不调用模型、不占用显存。特殊句式仍有可能判断错误，此时可在管理区将模式改为“标签模式”或“自然语言模式”。

混合模式会记录自然语言的起点和终点：自然语言内部的逗号保持在同一个文本块中，边界之后连续出现的质量、人数、外观、环境等标签会重新拆成独立标签。为了避免把普通英文从句误当标签，少于四项、缺少明显标签信号的短尾部不会被强行切分。

## 九、提示词诊断

检查器会提示：

- 未收录标签。
- 连续逗号和空标签。
- 中文标点。
- 重复标签。
- 括号或权重格式异常。
- 部分常见语义冲突。
- 当前解释来源和可信度。

诊断不会自动修改实际英文内容。

## 十、内置词库和个人词库

发布包包含七个小型词库，共约 1,073 个经过整理的中英词条：

- 基础常用词库。
- Anima 词库。
- 角色与作品词库。
- 姿势词库。
- 镜头构图词库。
- 服装词库。
- 成人内容词库（公开包默认停用，需要时由用户自行启用）。

成人词库是独立包，可在词库管理器中停用。词条只用于翻译和提示词识别，不代表任何模型一定能准确生成对应效果。

个人词库优先级最高。修改内置解释时不会覆盖内置文件，而是新建个人覆盖。个人词库保存在：

`data/user_tags.json`

卸载前如需保留个人词库，请先在词库管理器中导出。公开发布包中的个人词库始终为空。

## 十一、词库管理器

词库管理器支持：

- 按英文、中文、别名、分类和来源搜索。
- 收藏与取消收藏。
- 查看最近使用。
- 新建、修改、删除个人词条。
- 批量确认机器翻译。
- 批量修改分类和适用模型。
- 导入、导出个人词库。
- 导入、启停、导出和删除社区词库包。
- 修改内置或大型词库解释时创建个人覆盖。

个人词库单次最多导入 10,000 项，社区词库包最多 20,000 项。备份目录最多保留最近 50 个文件，避免无限增长。

节点中的搜索区统一命名为“词库搜索”，会查询当前启用的内置词库、个人词库、社区词库和可选大型词库。除英文、中文、别名和包含匹配外，还支持概念关联，例如搜索“丝袜”可返回连裤袜、长筒袜、过膝袜等相关标签；“黑丝袜”等带修饰词的查询会优先相关颜色组合。

搜索结果每次显示 40 项；仍有候选时可点击“搜索更多”继续加载，新增结果追加在下方并保持当前浏览位置，全部显示后会明确提示“没有更多结果”。大型数据库继续按需分页查询，不会一次性加载到节点或浏览器。未知英文标签旁提供“搜索候选”和“手动添加”，不要求购买或配置外部 API。

## 十二、大型 Danbooru 中英词库

由于社区数据的授权边界，本扩展公开发布包不包含 `danbooru_tags.sqlite3`。

未安装大型词库时，节点其他功能仍可正常使用。推荐用户自行从
`ffdkj/ffdkj-Danbooru_Tag-Chinese-English-Translation-Table` 下载 ZIP，解压得到
`tag.sqlite`，再按照随发布包提供的《大型词库手动安装说明.txt》进行本地转换。

转换工具同时兼容两种来源格式：

- ffdkj 原始 `tag.sqlite`，工具自动检查字段并转换完整词库。
- 旧版四列 TSV：`name、category、post_count、cn_name`。

为了避免下载路径、盘符和空格填写错误，推荐把来源 `tag.sqlite` 临时复制到扩展根目录，
确认 `tag.sqlite` 与 `tools/build_large_dictionary.py` 都存在后，再按照安装类型调用
ComfyUI 自带的 Python：

```powershell
# ComfyUI Desktop（在扩展根目录执行）
& "..\..\.venv\Scripts\python.exe" ".\tools\build_large_dictionary.py" ".\tag.sqlite"

# ComfyUI Windows Portable（在扩展根目录执行）
& "..\..\..\python_embeded\python.exe" ".\tools\build_large_dictionary.py" ".\tag.sqlite"
```

不同整合包的 Python 路径可能不同。发布包外的《大型词库手动安装说明.txt》包含
安装类型判断、`Test-Path` 检查、备用 Python 路径、成功验证及故障排查，请以该说明为准。

来源 SQLite 不能直接改名覆盖，因为拓展还需要规范化检索字段、分类文本、来源元数据和查询索引。转换时来源数据库以只读方式打开；已有拓展数据库会备份为
`data/danbooru_tags.sqlite3.previous`，成功后才替换。

大型词库使用只读 SQLite 和按需查询：

- 不把十几万条记录全部加载到浏览器。
- 只查询当前提示词中的未知标签或用户主动搜索的关键词。
- 不修改数据库原文件。
- 个人词库仍然拥有最高优先级。

## 十三、助手设置

支持三种服务类型：

### 纯词库

- 不需要 API。
- 只适合翻译已经收录的标签。
- 无法自动翻译复杂白话文和未收录内容；可先使用词库搜索查找候选或手动添加个人词条。

### Ollama 本地模型

- 默认地址：`http://127.0.0.1:11434`。
- 需要提前在 Ollama 中安装可用语言模型。
- 提示词不会离开用户自己指定的本地服务。

### OpenAI 兼容 API

- 填写 API 地址、模型名称和 API Key。
- 非本机 HTTP 地址会被拒绝，外部服务必须使用 HTTPS。
- 输入的提示词和自定义规则会发送给用户配置的服务商。
- 是否收费、记录数据或限制内容取决于对应服务商。

LM Studio 可直接使用助手设置中的“使用 LM Studio 本地预设”，默认地址为 `http://127.0.0.1:1234/v1`。本机默认配置不要求 API Key，但仍需在 LM Studio 中加载模型并填写对应模型 ID。

三个功能分别有独立规则：“仅翻译规则”“翻译并优化规则”“优化为 Anima 规则”。可以恢复默认值，也可以保存并测试连接。

## 十四、API Key 和本地接口安全

- API Key 不写入工作流、不返回浏览器、不进入公开发布包。
- API Key 与当前扩展安装实例、服务类型和 API 地址绑定。
- 更换服务商或 API 地址会自动清除旧 Key，必须重新输入。
- 完整卸载扩展后重新安装，会生成新的安装身份，旧配置和旧 Key 自动失效。
- 如需手动强制重置安装身份，可关闭 ComfyUI，删除 `data/runtime/installation_id`，再重新启动。
- 配置文件尽可能设置为仅当前系统用户可读写。
- `/bpi/*` 接口使用同源检查和临时会话令牌，降低跨站网页直接调用的风险。
- 助手请求限制为最多两个并发任务，并带有频率、长度和请求体积限制。

这些保护不是 ComfyUI 登录系统的替代品。不要把没有身份认证的 ComfyUI 直接开放到公网；能访问完整 ComfyUI 页面的人仍应被视为可信用户。

## 十五、多节点和浏览器状态

- 同一个 ComfyUI 页面中的检查器节点共享收藏、最近使用、词库更新和临时机器翻译状态。
- 收藏和最近使用保存在浏览器本地存储中。
- 临时机器翻译刷新网页后会清空，确认后的翻译才会写入个人词库。
- 鼠标位于标签区、文本框、管理表格等滚动区域时，只滚动当前区域，不缩放 ComfyUI 画布。

## 十六、卸载和重新安装

卸载前建议导出个人词库。

完整卸载步骤：

1. 关闭 ComfyUI。
2. 删除 `custom_nodes/ComfyUI-Bilingual-Prompt-Inspector` 文件夹。
3. 如需同时清除旧助手配置，可删除 ComfyUI 用户目录下的 `bilingual-prompt-inspector` 文件夹。
4. 重新安装干净发布包后，API 服务和 Key 必须重新配置。

直接合并覆盖旧目录属于“升级”，会保留个人词库、词库选择、大型数据库和安装身份；先删除旧目录再解压属于“重新安装”，会丢失扩展目录内尚未导出的个人数据。升级或重装前仍建议导出个人词库。

## 十七、常见问题

### 找不到节点

确认文件夹没有多嵌套一层，并检查 ComfyUI 启动终端是否有红色错误。安装后需要重启 ComfyUI。

### 页面还是旧界面

按 `Ctrl+F5` 强制刷新。自定义节点的 JavaScript 可能被浏览器缓存。

扩展会同时兼容传统节点和 ComfyUI 0.36.0 的现代节点设计：节点顶部的 ComfyUI 原始英文文本框在两种模式下都保持可见，展开或收起标签管理时节点会重新适配内容高度。

### 翻译按钮提示需要模型

当前处于纯词库模式，并且输入包含未收录词汇或白话文。可以先用“词库搜索”查找候选或手动添加个人词条；需要模型能力时可选择免费的本地 Ollama / LM Studio，外部付费 API 不是必需项。

### 大型词库显示未安装

这是公开包的正常状态。大型数据库是可选组件，需要用户自行下载来源数据并本地转换。不要把 ffdkj 的 `tag.sqlite` 直接改名为 `danbooru_tags.sqlite3`。

### 切换 API 地址后 Key 消失

这是安全设计。旧 Key 不会被自动发送到新的服务器地址，请重新输入对应地址的 Key。

### 标签识别不正确

尝试手动选择“标签模式”或“自然语言模式”。自动模式无法覆盖所有特殊写法。

## 十八、已知边界

- 本扩展是提示词工具，不保证某个标签一定被模型准确执行。
- 自动分类、自动翻译和模型优化结果都需要人工复查。
