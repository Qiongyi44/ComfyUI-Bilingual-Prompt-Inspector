# 设计决策记录

本文解释当前实现“为什么这样设计”。后续维护者如需推翻某项决策，应先补充测试、说明兼容影响，并更新本文件。

## 1. 采用无损透传节点，而不是后端自动改写

决定：Python 节点始终原样返回英文输入。

原因：翻译、分类和模型输出都可能出错。把这些能力放入生成必经路径会使旧工作流结果不可预测，也会让助手不可用时阻断生图。因此辅助功能在浏览器侧工作，失败后仍可正常运行工作流。

## 2. 原生英文控件是唯一真值，界面只是编辑投影

决定：保留 ComfyUI 原生 `STRING` 控件负责序列化和输出，前端增加文本编辑/标签联动双模式。

原因：早期只依赖浏览器原生选区，受主题、焦点和 ComfyUI 控件结构影响，高亮经常不可见。完全替换原生控件又容易破坏工作流保存。双模式既保留兼容性，又让英文、中文和明细行拥有一致的可视选择状态。

## 3. 翻译、优化和同步必须分阶段

决定：设置“仅翻译”“翻译并优化”“优化为 Anima”“同步到英文输出”四个独立动作。

原因：翻译与提示词创作不是同一任务。用户需要看见模型做了什么，并决定是否覆盖实际输出。每个动作使用独立规则，避免一个通用提示词同时承担忠实翻译、扩写和格式整理而行为混乱。

## 4. Anima 排序只在按下按钮后执行

决定：不在输入时自动排序。

原因：输入过程中重排会打断编辑，也可能错误分类角色、作品或白话文。手动执行、稳定排序和应用前预览让用户保留控制权。排序只移动现有项目，不负责补全内容。

## 5. 自然语言作为完整块保存

决定：一旦确定自然语言边界，块内逗号不再逐项拆分。

原因：英文白话文天然包含大量逗号。按逗号全部拆分会造成“一句话被后台显示成多个未知标签”、单项翻译误拦截和删除破坏句子。代价是不能在标签视图里逐词删除自然语言，需返回文本编辑模式修改。

## 6. 混合识别采用双边界与保守后缀判断

决定：同时记录白话文起点和终点；只有后续连续短项及明显标签信号充足时才恢复标签拆分。

原因：只支持“标签 + 末尾白话文”无法处理模型返回的白话文后标签或夹心结构；过于激进的后缀判断又会拆碎普通从句。因此以“不误拆白话文”为优先，疑难输入交给手动模式。

## 7. 双击标签统一用于权重，而不是中文编辑

决定：英文和中文标签双击均打开权重编辑器；中文释义修改放在明细行/词库管理器。

原因：标签的主要结构化编辑动作是修改实际英文权重，且中英文视图必须行为一致。释义属于词库数据，不应与工作流提示词编辑混在同一手势中。

## 8. 大型词库按需查询，不加载到前端

决定：几十万条词库只保存在后端只读 SQLite；输入未知标签时批量精确查询，主动搜索时限量模糊查询。

原因：全部加载会增加启动时间、JSON 传输、浏览器内存、索引构建和多节点重复缓存压力。大型库并不需要编辑，个人修改用覆盖层即可。按需查询也便于把第三方数据库从公开包中剥离。

## 9. 第三方大型数据库由用户本地转换

决定：仓库和 Release 不提供 `tag.sqlite` 或 `danbooru_tags.sqlite3`。

原因：ffdkj 来源在整理时未发现明确许可证，扩展不能把第三方数据库包装成自有资产重新分发。构建工具只读来源文件，生成适合当前索引结构的本地数据库，并在成功后原子替换旧库。

历史说明：第七至十六版测试库来自 Kohya-LoRA-Tool 附带的混合 TSV；第十七版起推荐用户自行下载 ffdkj 原始 `tag.sqlite`。这两个“直接来源”不能混写。

## 10. 个人词库采用覆盖层

决定：内置包、社区包和大型库不原地编辑，用户修改写入 `user_tags.json`。

原因：升级时可以替换公共词库而不丢失个人调整，也能明确数据所有权。个人词库优先级最高，删除个人覆盖后自然恢复底层解释。

## 11. 收藏与待确认使用不同持久化策略

决定：收藏和最近使用保存在浏览器本地；待确认机器翻译只存在当前页面共享内存；确认后才写个人词库。

原因：收藏是界面偏好，适合长期保存；未审核模型输出不应自动成为词库事实。多节点通过页面级同步中心广播状态，避免同一页面各节点显示不同收藏和待确认数量。

## 12. 助手完全独立于其他提示词插件

决定：翻译、优化、单项解释和批量翻译全部调用扩展自身 `/bpi/assistant/*` 接口。

原因：依赖另一个提示词助手会使扩展无法独立分享，规则和 API 配置也难以控制。独立助手支持纯词库、Ollama 和 OpenAI 兼容 API，并明确由用户主动发起请求。

## 13. API Key 与安装身份和端点绑定

决定：Key 留在后端，改变服务类型或地址就清除；完整重装生成新安装身份后旧配置失效。

原因：避免把 A 服务商的 Key 意外发给 B 地址，也避免公开包、工作流或浏览器读接口泄露凭据。当前实现是本地风险降低措施，不等同于系统级密钥库。

## 14. 本地接口采用同源 + 临时令牌 + 限流

决定：除会话入口外所有路由都要求随机会话令牌并验证同源，助手另有限流、并发和体积限制。

原因：ComfyUI 自定义路由原本可能被其他网页直接请求。这些措施能阻挡常见跨站调用和失控请求，但不会把 ComfyUI 变成多用户安全服务，因此 README 和安全策略必须保留“不要直接暴露公网”的边界声明。

## 15. 滚轮在捕获阶段隔离

决定：鼠标位于扩展滚动区时，无论是否已到滚动边界，都不让事件继续触发画布缩放。

原因：ComfyUI 画布可能比节点 DOM 更早处理滚轮；普通冒泡阶段阻止不稳定。只在声明的可滚动区域拦截，节点其余区域仍保留画布缩放。

## 16. 作者入口放在节点底部

决定：作者信息采用低干扰入口，固定跳转到无跟踪参数的 Bilibili 空间，并使用外部浏览器安全属性。

原因：保证可见但不挤占主要操作区，不内嵌远程页面，也不在节点加载时产生网络访问。

## 17. 明确没有采用的方案

- 未采用“输入即自动排序”：会打断编辑且分类存在不确定性。
- 未采用“把全部大型词库送入浏览器”：性能和数据授权均不合适。
- 未采用“直接修改大型数据库”：升级冲突且破坏只读来源边界。
- 未采用“翻译后立即覆盖英文”：模型错误缺少人工确认窗口。
- 未采用“把每个逗号都视为标签”：会拆碎自然语言。
- 未采用“继续依赖外部提示词助手插件”：不利于独立安装和分享。
- 未采用“仅靠文本框原生选区表示联动”：跨主题和控件版本不可靠。

## 18. 版本语义

- `v1` 至 `v19` 是功能演进代次，详细变化见 `DEVELOPMENT_HISTORY.md`。
- GitHub 首个公开正式 Release 使用 `v1.0.0`。
- 后续发布应使用语义化版本号，不要把内部演进代次和公开版本号混为一谈。
- 兼容修复递增补丁号；向后兼容的新功能递增次版本；破坏工作流或数据格式时才递增主版本，并提供迁移说明。
