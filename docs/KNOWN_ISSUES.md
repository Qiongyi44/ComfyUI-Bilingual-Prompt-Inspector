# 已知边界、风险与回归重点

本文不是尚未修复 Bug 的承诺清单，而是维护时必须持续关注的风险目录。确认修复或新增风险后应更新状态和测试。

## 1. ComfyUI 前端结构变化

状态：持续风险。

英文双模式仍需要找到 ComfyUI 原生文本控件并保持双向同步。ComfyUI/PrimeVue 若改变 DOM Widget、控件索引或节点生命周期，可能出现标签视图不更新、节点高度异常或工作流恢复异常。

缓解：避免依赖单一 DOM 层级；升级 ComfyUI 后手测空节点、旧工作流、复制节点、撤销和刷新。

## 2. 自动模式无法覆盖所有自然语言

状态：设计边界。

解析器使用本地启发式，不理解所有英语句法。极短白话、专有名词串、包含大量标签式短语的句子及非英语内容可能误判。

缓解：保持手动“标签/自然语言”模式；每次增强同时加入反例，优先避免破坏自然语言。

## 3. 词库命中不等于模型支持

状态：设计边界。

词库只能说明某个英文词条和中文解释的对应关系，不能证明 Anima 或某个 LoRA 一定学习过该概念，也不能保证生成效果。

缓解：UI 和文档保持“解释/建议”措辞，不把词库结果描述为模型能力认证。

## 4. 外部模型输出不可完全信任

状态：持续风险。

助手可能增删人物、误译动作、改变安全等级、输出不支持标点或拒绝某些内容。扩展的结果清理只能检查一部分格式，不能验证全部语义。

缓解：保持暂存、预览和人工同步；关键语义由用户逐项检查；失败不得覆盖实际输出。

## 5. API 配置不是系统密钥库

状态：安全边界。

配置文件尝试限制为当前用户访问，但 Windows 权限、备份软件和有本机权限的进程仍可能读取。安装身份绑定用于防止误带和误发，不是强加密。

缓解：不得把配置文件加入备份包或 Issue；未来若引入系统凭据管理器，需要兼容迁移和跨平台方案。

## 6. 本地路由不是登录系统

状态：安全边界。

会话令牌、同源检查和限流可降低跨站滥用，但任何能加载完整 ComfyUI 页面的人通常也能使用扩展功能。未认证 ComfyUI 暴露公网仍然危险。

缓解：继续保留安全声明；不要承诺公网保护。对路由新增功能时复用 `protected_route`，不要注册无保护的写接口。

## 7. URL 配置与内网访问

状态：受信任用户边界。

助手后端会请求用户配置的本地或 HTTPS 地址。对单用户本地 ComfyUI 这是预期功能；在多人共享实例上，配置权限可能被用来访问服务端可达地址。

缓解：共享部署必须由外层限制可信用户；若未来支持多用户，需要独立权限、地址策略和审计，而不是继续扩大当前本地模型假设。

## 8. 浏览器状态只在当前来源下共享

状态：设计边界。

收藏、最近使用和部分尺寸依赖浏览器本地存储。同一 ComfyUI 使用不同域名、端口、浏览器配置或隐私模式时不会自动共享；待确认翻译刷新页面后清空。

缓解：不把它描述成账户同步；重要词条必须确认保存或导出个人词库。

## 9. 大型数据库安装路径易出错

状态：已提供说明，仍需关注。

用户常见问题包括双盘符路径、在 ZIP 预览中操作、调用 Windows Store Python 空壳、使用另一套 ComfyUI 的 Python、直接改名数据库和数据库被占用。

缓解：维护 `release_docs/大型词库手动安装说明.txt` 的相对路径方案、`Test-Path` 预检、成功路径验证及三类 ComfyUI 命令。

## 10. 大型库来源许可与内容准确性

状态：第三方边界。

ffdkj 来源在项目整理时未看到明确开源许可证，翻译规模大且可能包含错误、成人词和社区偏好。

缓解：不再分发数据库，只提供用户本地转换工具；保留来源声明；不要把第三方翻译写成项目原创。

## 11. 个人词库位于扩展目录

状态：数据丢失风险。

直接删除扩展目录会同时删除 `data/user_tags.json` 和备份。覆盖升级通常保留，完整卸载不会保留。

缓解：卸载/换电脑前导出个人词库；发布脚本不得把开发机个人词库带入包。未来如迁移到 ComfyUI 用户目录，需要提供旧路径迁移。

## 12. 社区包和个人导入的资源压力

状态：已有限制。

个人导入上限 10,000，社区包上限 20,000，但多个大型社区包同时启用仍会增加每次快照的 JSON 体积和浏览器索引时间。

缓解：大型数据继续走 SQLite 按需查询；不要通过放宽 JSON 包上限替代数据库方案。

## 13. 主前端文件体积较大

状态：维护性风险。

`js/bilingual_prompt.js` 同时承担节点 UI、助手设置和词库管理器，功能耦合较多。局部改动可能影响生命周期、尺寸和跨节点状态。

缓解：新增纯逻辑优先拆到小模块并写独立测试；如拆分 UI 模块，必须保持加载顺序和旧节点行为，不宜一次性大重写。

## 14. 性能风险

状态：已有测试，需持续观察。

超长提示词、多节点、多个社区包和频繁重新渲染可能造成卡顿。大型库虽按需查询，但错误地清空缓存或逐标签发请求会放大延迟。

缓解：保留批量精确查询、搜索防抖、命中/未命中缓存和固定滚动区域；性能修改要运行 `test_performance.mjs` 并进行多节点手测。

## 15. 默认规则升级

状态：兼容性风险。

代码只应在用户仍使用可识别的旧默认规则时自动升级，不能覆盖用户自定义规则。新增默认规则版本时若只做全文相等判断，需要保留所有历史默认文本或明确迁移条件。

缓解：为迁移补充测试；自定义内容优先保留；公开说明默认规则变化。

## 16. 当前重点回归缺陷

以下问题历史上已经修复，但极易因改动复发：

- 标签多时节点被无限拉长。
- 滚动节点内部时缩放 ComfyUI 画布。
- 多节点收藏和待确认不同步。
- 中文选中后英文没有可见高亮。
- 英文普通文本框无法稳定表现联动选区。
- 白话文被整段当作一个标签，或被逗号拆成多个标签。
- 白话文末尾逗号导致整段无法识别。
- 自然语言翻译因译文逗号较多而被“多个标签”校验拦截。
- 重复标签删除或改权重时影响错误的出现位置。
- 更改 API 服务商或地址后继续复用旧 Key。
- 公开包意外携带大型数据库、个人词库或助手设置。

上述各项即使已有自动测试，也应在涉及对应区域的发布中做最小人工复验。
