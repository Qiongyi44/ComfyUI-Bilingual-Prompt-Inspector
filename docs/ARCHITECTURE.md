# 架构说明

本文面向后续维护者，记录 ComfyUI 双语提示词检查器当前公开源码的真实结构。使用方法以根目录 `README.md` 为准；版本演进以 `DEVELOPMENT_HISTORY.md` 为准。

## 1. 核心目标与不可破坏约束

本扩展的首要目标不是“替用户改写提示词”，而是在不破坏原始英文输出的前提下提供检查、翻译、整理和词库管理能力。

必须长期保持以下约束：

1. Python 节点 `BilingualPromptInspector` 是无损 `STRING -> STRING` 透传节点。
2. 工作流实际输出只取自原生 `text` 控件；中文解释、诊断、收藏和临时翻译不能进入模型条件。
3. 翻译、优化和排序结果必须先预览或暂存，由用户主动确认后才能覆盖英文输出。
4. 个人 API Key、个人词库、运行时安装身份和可选大型数据库不能进入公开源码或发布包。
5. 内置与大型词库保持只读；用户修改它们时创建个人覆盖。
6. 自动识别只提供启发式判断，不能假装拥有绝对语义正确性；始终保留手动模式。

## 2. 组件职责

### Python 节点层

- `nodes.py`
  - 定义唯一工作流节点 `BilingualPromptInspector`。
  - 输入为多行动态提示词 `text`，输出为同一字符串。
  - 不执行翻译、解析、词库搜索或网络请求。
- `__init__.py`
  - 注册节点映射、显示名称和 `WEB_DIRECTORY`。
  - 导入 `server.py`，使本地 `/bpi/*` 路由随扩展启动注册。

### 后端服务层

- `server.py`
  - 注册助手、个人词库、词库包和大型词库的本地接口。
  - 执行同源检查、临时会话令牌校验、请求体限制、助手频率限制和并发限制。
  - 只在用户主动调用时访问配置的 Ollama 或 OpenAI 兼容服务。
- `assistant_store.py`
  - 保存助手服务类型、地址、模型、三套规则和 API Key。
  - API Key 不通过读取接口返回前端。
  - Key 与“安装身份 + 服务类型 + API 地址”绑定；地址或服务商变化后自动清除旧 Key。
  - 负责翻译方向判断、纯词库翻译和 Anima 输出标点清理。
- `dictionary_store.py`
  - 加载内置包、社区包、个人词库及可选大型 SQLite。
  - 校验词条结构、控制导入数量、生成原子写入和有限备份。
  - 大型库使用 SQLite 只读连接和索引查询，不整体载入内存。

### 浏览器前端层

- `js/bilingual_prompt.js`
  - 创建节点内全部可视化界面。
  - 保持 ComfyUI 原生英文控件可见，并将其作为工作流真值来源。
  - 管理英文文本/标签双模式、绿色中文镜像、联动选择、权重、删除、撤销重做、助手设置、词库管理器及跨节点刷新。
- `js/parser.js`
  - 非破坏性切分标签，保留原始字符位置。
  - 识别纯标签、纯自然语言、指令正文和双边界混合文本。
  - 提供按具体出现位置删除、修改权重、机器翻译结果校验和语法诊断。
- `js/anima_sorter.js`
  - 把已解析内容稳定分类为九段 Anima 顺序。
  - 只重新排列现有项目，不主动生成新标签。
- `js/dictionary_tools.js`
  - 负责收藏/最近使用规范化、搜索排序和导入预览等纯逻辑。
- `js/panel_sync.js`
  - 提供当前页面内的发布/订阅中心，使不同节点共享收藏、临时机器译和词库更新通知。
- `js/wheel_guard.js`
  - 在捕获阶段隔离扩展内部可滚动区域的滚轮事件，避免误缩放 ComfyUI 画布。

### 数据与工具

- `data/packs/*.json`：七个可独立启停的小型内置词库。
- `data/packs/manifest.json`：词库包顺序、元数据、只读状态和默认启用状态。
- `data/base_tags.json`：旧版兼容数据。
- `tools/build_large_dictionary.py`：把 ffdkj `tag.sqlite` 或旧四列 TSV 转换为扩展查询格式。
- `tools/build_community_release.ps1`：生成排除本机数据的公开发布包。
- `tests/`：解析、双边界、排序、跨节点同步、滚轮、作者链接、性能、存储及数据库转换测试。

## 3. 数据流

### 普通检查流程

```text
ComfyUI 原生 text 控件（工作流真值）
        │
        ├─→ Python pass_through → 英文提示词输出
        │
        └─→ 浏览器解析器
              ├─→ 英文标签视图
              ├─→ 中文镜像与来源/可信度
              ├─→ 语法和冲突诊断
              └─→ 未命中项批量查询大型词库
```

### 翻译与优化流程

```text
绿色草稿框
  → 用户点击仅翻译 / 翻译并优化 / 优化为 Anima
  → /bpi/assistant/run
  → 纯词库、Ollama 或 OpenAI 兼容服务
  → 结果写回绿色暂存区
  → 用户点击“同步到英文输出”并确认
  → 更新原生 text 控件
```

任何助手失败都不应中断 Python 节点的英文透传。

### 词库查询优先级

从高到低：

1. 个人词库及个人覆盖。
2. 当前启用的小型内置/社区词库包，按清单优先级合并。
3. 可选大型 Danbooru SQLite 精确查询。
4. 当前页面临时机器翻译，仅作为待确认显示，不自动持久化。

个人覆盖只覆盖同一规范化英文键。规范化过程会统一大小写、下划线、空格，但界面仍应尽量保留用户原始文本。

## 4. 状态与持久化边界

| 状态 | 保存位置 | 是否进入工作流 | 是否允许发布 |
|---|---|---:|---:|
| 英文实际提示词 | ComfyUI 原生 `text` 控件 | 是 | 随用户工作流，不属于扩展发布包 |
| 版面展开、高度、收藏、最近使用 | 浏览器本地存储 | 否 | 否 |
| 临时机器翻译/待确认 | 当前页面共享内存 | 否 | 否，刷新即失效 |
| 个人词库 | `data/user_tags.json` | 否 | 否，干净发布包必须为空或不存在 |
| 个人词库备份 | `data/backups/` | 否 | 否 |
| 社区包启停 | `data/pack_settings.json` | 否 | 不应携带个人选择 |
| 大型词库启停 | `data/large_dictionary.json` | 否 | 不应携带个人选择 |
| 大型词库 | `data/danbooru_tags.sqlite3` | 否 | 禁止打包或提交 |
| 助手配置 | ComfyUI 用户目录 `bilingual-prompt-inspector` | 否 | 禁止打包或提交 |
| 安装身份 | 扩展 `data/runtime/installation_id` | 否 | 禁止打包或提交 |

## 5. 解析模型

解析器必须同时满足“能联动具体标签”和“不破坏自然语言”两个互相拉扯的目标。

- `splitPrompt` 按顶层逗号切分，同时保护括号、权重和尖括号语法。
- `detectInputMode` 根据标签数量、句法信号和自然语言结构判断模式。
- 混合模式记录 `naturalStart` 与 `naturalEnd`，因此支持：
  - 标签 → 白话文；
  - 白话文 → 标签；
  - 标签 → 白话文 → 标签。
- 自然语言块内部的逗号不能继续拆成标签。
- 白话文末尾逗号不能被误判为空标签；纯标签流连续逗号仍应报警。
- 后置标签只有在连续短项和质量、人数、外观、环境等强信号足够时才重新拆分，以避免把英文从句误当标签。

所有标签都携带原文起止位置。删除、权重修改和三处联动必须依赖“具体出现位置”，不能只按规范化文本匹配，否则重复标签会一起被改动。

## 6. Anima 排序模型

当前顺序固定为：

1. 质量、元数据、年份、安全。
2. 人数。
3. 角色。
4. 作品/系列。
5. 画师。
6. 外观。
7. 其他标签（表情、动作、姿势、镜头等）。
8. 环境、背景、光线。
9. 自然语言。

分类优先使用词库元数据，再使用本地规则。排序必须稳定，必须保留标签正文、权重、`@`、`<...>`、`BREAK`/`AND` 等结构，并在应用前预览。

## 7. 本地接口与安全边界

- `/bpi/session` 仅在通过同源检查后发放进程级随机令牌，并禁止缓存。
- 其他 `/bpi/*` 路由都要求 `X-BPI-Token` 且再次检查同源。
- 助手请求体上限为 256 KB；一般 JSON 上限为 8 MB。
- 助手最多两个并发任务，默认每分钟最多 30 次请求。
- 外部非本机 HTTP 地址被拒绝，外部服务要求 HTTPS。
- Key 只由后端保存；公开配置只返回 `api_key_configured` 布尔值。

这套保护用于减少跨站网页和误操作风险，不是登录系统、防火墙或多用户权限隔离。能访问完整 ComfyUI 页面的人仍属于可信用户。不得宣称扩展可以安全地把未认证的 ComfyUI 暴露到公网。

## 8. 兼容性重点

- 不要更改节点类名 `BilingualPromptInspector`、输入名 `text`、返回类型或类别，除非提供迁移方案。
- 原生文本控件即使由扩展提供额外编辑投影，也必须保持正常序列化和输出。
- 前端依赖 ComfyUI DOM Widget/PrimeVue 文本控件结构，升级 ComfyUI 后应重点回归空节点、旧工作流、文本编辑和标签联动。
- `panel_sync` 只解决同一页面多节点同步；跨标签页、跨浏览器和跨设备不是当前承诺。
- 任何解析增强都要同时测试末尾逗号、权重、重复标签、自然语言多逗号和夹心结构。
